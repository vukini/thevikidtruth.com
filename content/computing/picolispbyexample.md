### The plain idea

This page is my personal problem set for learning [PicoLisp](picolisp.md) by *doing*: a collection of small, interesting programming problems worked through in PicoLisp, inspired by the book [PicoLisp by Example](https://github.com/tj64/picolisp-by-example). The best way to learn a Lisp is not to read about it but to solve little puzzles in it, so that is what I collect here.

### Why learning by example works

PicoLisp is small and unusually consistent, which makes it ideal for this. Each problem, drawn from the classic "Ninety-Nine Lisp Problems" and the Rosetta Code tasks, is a self-contained chance to practise one idea: recursion, list manipulation, higher-order functions. You read the problem, try it yourself, then compare with a worked solution. The friction of actually typing and running code is where the learning happens.

### An everyday analogy

You do not learn a language from a phrasebook; you learn it by having real little conversations. These problems are those conversations: short enough to finish, varied enough to stretch you, and each one leaving you a bit more fluent.

### A note on the sources

The "99 Lisp Problems" began life as a **Prolog** problem list by Werner Hett and were adapted for Lisp; **Rosetta Code** collects the same task solved across hundreds of languages, which makes it a superb way to see how PicoLisp's approach differs from, say, [Python](python.md) or [Scheme](scheme.md). I am not reproducing the book, just using it as a springboard for my own list of problems and solutions.
